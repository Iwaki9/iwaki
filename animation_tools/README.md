# Помощник анимации по озвучке

Офлайн-дополнение к Python-движку из `part1_инструкции_движок_персонажи.zip`. Оно помогает найти реплики в истории, назначить говорящих и подобрать жесты; затем привязывает их к словам в `words.json` и создаёт обычные для движка списки `clips` и `talk`. Движок, HTML-студия и архивы при этом не меняются.

**Это не готовый фильм и не автоматическое создание сцен.** Планы, фон, позиции и камера по-прежнему задаются в `scenes.py`. Чтобы результат появился при рендере, необходимо подключить помощник к `build()` (ниже). В архиве «Три дня до рассвета» готового `scenes.py` для этого проекта пока нет.

## Быстрая проверка на существующих архивах

Нужен Python **3.10 или новее**. Для самого помощника дополнительные библиотеки и интернет не нужны. Находясь в корне этого репозитория, запустите:

```bash
python -m animation_tools check --plan "animation_tools/examples/tri_dnya_dialogue.json" --words "part4_озвучка.zip::projects/03_tri_dnya/audio/words.json" --anims "part1_инструкции_движок_персонажи.zip::engine/anims/anims.json" --offset 6
```

Без распаковки появятся четыре настоящие реплики Лесника и рассказчика с найденным временем и предложенным движением. Например, фраза «Знаю, что не спишь» начинается на **143,90 с фильма**, поскольку в примере добавлены 6 с заставки. Пример — только небольшой фрагмент для проверки, не полная разметка.

## Рабочий процесс

1. Распакуйте архивы `part1`…`part4` в одну папку, как описано в `ЧИТАЙ_СНАЧАЛА.txt`. Скопируйте папку `animation_tools/` из репозитория в этот же корень, рядом с `engine/`, `anim/` и `projects/`. В командах ниже рабочая папка — этот корень.
2. Создайте черновик из истории и таймингов:

   ```bash
   python -m animation_tools draft --story "projects/03_tri_dnya/история.txt" --words "projects/03_tri_dnya/audio/words.json" --out "projects/03_tri_dnya/auto_draft.json"
   ```

   Можно читать файлы прямо из ZIP, используя `архив.zip::путь/внутри` — как в быстрой проверке. Файл результата при этом создаётся на диске. Существующий файл не перезаписывается без `--force`.

3. **Проверьте черновик и назначьте роли.** `words.json` не хранит сведения о говорящем: программа не может надёжно отличить персонажа от закадрового рассказчика или мысли. Черновик нельзя применить, пока роли не назначены. Для пошаговой проверки в терминале:

   ```bash
   python -m animation_tools review --draft "projects/03_tri_dnya/auto_draft.json" --words "projects/03_tri_dnya/audio/words.json" --role "лесник=lesnik_tulup_v1" --role "рассказчик=rasskazchik_street_v3" --role "макс=maks_kurtka_v1" --offset 6 --out "projects/03_tri_dnya/auto_animation.json"
   ```

   Для каждого фрагмента введите номер говорящего или `s`, чтобы пропустить закадровый текст / ошибочно найденный фрагмент. Дальше показано предложение: `Enter` принимает его, `keep` сохраняет исходную позу, ID (например, `wave`) задаёт анимацию явно, `@кивает` подбирает её по описанию, `?` показывает доступные анимации. После ввода нового варианта нажмите `Enter` для подтверждения. `auto` возвращает автоматический выбор. Сами движения можно посмотреть в `2d_character_motion_studio_46.html`, а их вид на персонажах — в кадрах движка. Если отменить проверку, выходной файл не создаётся. Если реплики конфликтуют по времени, конфликтующий фрагмент пропускается с сообщением.

   Черновик ищет **только абзацы, начинающиеся с длинного тире**; это эвристика, а не полноценное понимание текста. Он перечисляет пропущенные возможные авторские ремарки; возможны ошибки и пропуски. Перепроверьте границы реплик по истории и, если нужно, исправьте итоговый JSON вручную.
4. Проверьте итоговый план:

   ```bash
   python -m animation_tools check --plan "projects/03_tri_dnya/auto_animation.json" --words "projects/03_tri_dnya/audio/words.json" --offset 6
   ```

   Показываются время фильма, роль, движение и причина выбора. `--offset` — задержка начала озвучки относительно фильма; для другого проекта используйте его собственное `voice_offset`. Эта команда не видит состав планов и не проверяет, действительно ли говорящий в кадре.
5. Подключите план к `scenes.py` перед возвратом результата из `build()`:

   ```python
   # В начале существующего scenes.py:
   import sys
   from pathlib import Path

   ROOT = Path(__file__).resolve().parents[2]  # корень рядом с engine/ и animation_tools/
   if str(ROOT) not in sys.path:
       sys.path.insert(0, str(ROOT))
   from animation_tools import apply_plan, load_animation_ids, load_json
   ```

   ```python
   # В конце build(ctx), ПОСЛЕ добавления всех shots, до return:
   shots, report = apply_plan(
       shots,
       duration,                       # общая длительность фильма
       ctx["words"],                   # Words из существующего движка
       load_json(Path(__file__).with_name("auto_animation.json")),
       load_animation_ids(ROOT / "engine" / "anims" / "anims.json"),
       voice_offset=OFFSET,           # тот же OFFSET, что возвращается как voice_offset
   )
   for warning in report["warnings"]:
       print("[автоанимация]", warning)
   # В существующем return используйте обновлённый shots;
   # остальные поля (duration, voice_offset, sfx, music и т. д.) не меняйте.
   ```

   Помощник возвращает **новый** список планов; исходный `shots` и JSON он не изменяет. Для нужной роли актёр должен присутствовать в `shot["actors"]` с соответствующим `pack`. Если его нет на весь фрагмент или его часть, в `report["warnings"]` будет предупреждение. Это проверка наличия в списке актёров, а не проверка кадрирования: персонаж может оказаться за краем кадра или закрыт другим объектом. Проверьте кадры/черновик сами.

Для самого рендера остаются прежние зависимости движка и `audio/narration.wav`. Например, если в архиве есть только MP3:

```bash
ffmpeg -i "projects/03_tri_dnya/audio/narration.mp3" -ac 1 -ar 48000 "projects/03_tri_dnya/audio/narration.wav"
```

Рот управляется **существующим механизмом движка по громкости wav**, только во время назначенной реплики. Это не распознавание фонем и не синтез речи. Проверьте, что в паке персонажа есть подходящие формы рта и что он виден. Озвучку, видео и персонажей помощник не генерирует.

## Формат плана

Можно исправлять файл после `review` или создать его вручную. Полностью проверяемый пример: [`examples/tri_dnya_dialogue.json`](examples/tri_dnya_dialogue.json).

```json
{
  "version": 1,
  "roles": {
    "лесник": {"pack": "lesnik_tulup_v1"}
  },
  "cues": [
    {
      "id": "лесник-предупреждение",
      "kind": "speech",
      "role": "лесник",
      "text": "Знаю, что не спишь",
      "paragraph": 9,
      "animation": "auto",
      "action": "кивает",
      "at": "не спишь",
      "motion_duration": 1.2
    }
  ]
}
```

- `text` — **непрерывный фрагмент реальных слов** из `words.json`, без авторских слов посреди реплики. Большие реплики можно разбить на несколько. Регистр, знаки препинания, `ё`/`е` и знаки ударения не мешают поиску; написание слов и разбиение по пробелам/дефисам должны совпадать.
- `paragraph` необязателен, но полезен для одинаковых фраз. Если совпадений всё ещё несколько, укажите `occurrence: 1` (или 2 и т. д., считая внутри выбранного абзаца). Неоднозначные и не найденные фразы вызывают ошибку, а не привязываются наугад.
- `kind: "speech"` добавляет интервал говорения. `kind: "action"` привязывает только движение к фразе повествования, не открывая рот. По умолчанию используется `speech`.
- `animation: "auto"` выбирает из простых правил по явному `action`, а вопросу без описания предлагает `thinking`; без надёжной подсказки сохраняется исходная поза. Это **подсказки, не ИИ**; по смыслу реплики нельзя надёжно угадать действие. `"keep"` не добавляет жест. Любой другой ID проверяется по `engine/anims/anims.json`. Значение `animation` можно не указывать: тогда действует `auto`.
- `at` — слово или фраза внутри `text`, на которой начинается жест. По умолчанию — начало реплики. При нескольких совпадениях `at` используйте `at_occurrence`. Время рта не меняется. `motion_duration` ограничивает жест (по умолчанию 2,4 с, но не дольше конца фрагмента); `speed` по умолчанию 0,8, `blend` — 0,28 с. Затем возвращается исходная анимация. Ходьба, бег и подобные циклы двигают ноги **на месте**: траектория `path` задаётся отдельно. Взаимодействие двух персонажей и реквизит автоматически не согласуются.
- Если в одном плане два актёра с одинаковым `pack`, задайте каждому дополнительное поле `animation_role`, например `"animation_role": "первый"`, а роли — селектор `{"pack": "имя_пака", "tag": "первый"}`. Неоднозначный выбор актёра вызывает ошибку.

Реплика может пересекать несколько планов: интервалы речи обрезаются по границам планов, а фаза жеста продолжается после склейки. Существующие `talk` по умолчанию **объединяются** с новыми. Чтобы заменить их только у актёров и планов с назначенными речевыми фрагментами, явно передайте `talk_policy="replace"` в `apply_plan`. Проверьте это особенно внимательно: замена удалит и другие прежние интервалы речи этого актёра в затронутом плане. Планы без речевых фрагментов и чужие актёры не затрагиваются.

Ручные смены `clips` имеют приоритет перед автоматически добавленным жестом. Автоподсказка не заменяет существующую не-`idle` позу (например, сидение): об этом будет предупреждение. Если осознанно хотите заменить её на время реплики, задайте конкретный ID в `animation`; появится предупреждение для визуальной проверки. Настройки лица, позы `offsets`, пути и света не редактируются.

При замене озвучки помощник заново ищет фразы при каждом вызове `build()` — времена в план не зашиты. Если текст, разбиение на абзацы или число повторов изменились, запустите `check` и заново проверьте разметку. Короткие слова менее 0,02 с и пересечения времён разных слов отмечаются предупреждением: это может быть ошибка выравнивания. При таком пересечении соседний жест может быть сокращён до начала следующего.

## Проверки разработчика

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют повторяющиеся фразы, смещение заставки, разбиение между планами, сохранность ручных поз, назначение ролей и работу с реальными словами из архивов. Если доступны `numpy`, OpenCV и Pillow, дополнительно запускается CPU-проверка с оригинальным `compose.py`, запечёнными движениями, паком Лесника и реальным фоном. Если зависимости отсутствуют, только этот тест пропускается.
